* **Objective:** Implement the core business interactors in the `:usecases` module that orchestrate application workflows between domain repositories and the presentation layer (`:app`). This includes retrieving Phase 1 match fixtures (`GetPhase1GamesUseCase`, `GetGameByRoundUseCase`), synthesizing match context to request AI tactical insights and practice drills (`GenerateInsightsUseCase`, `GetPracticeDrillsUseCase`), and coordinating single-thread AI chat interactions grounded in match history (`GetChatMessagesUseCase`, `SendChatMessageUseCase`).
* **Identified Ambiguities / Assumptions:**
  - *Clean Architecture Boundary Violation Rectification*: `usecases/build.gradle.kts` currently contains `implementation(project(":data"))`. Per `ARCHITECTURE.md` and Clean Architecture principles, `:usecases` MUST ONLY depend on `:domain` (plus test dependencies). It MUST NOT depend on `:data`. This dependency must be removed immediately.
  - *Context Formatting & Constraint #11*: Constraint #11 mandates that "Repositories MUST NOT inject or depend on other repositories. Any cross-aggregate coordination or contextual enrichment (e.g. passing Phase 1 match context to the AI repository) MUST be orchestrated by Use Cases in the :usecases layer." Because `AiAnalysisRepository` and `ChatRepository` require a textual `gameContext: String`, and `:usecases` cannot access `:data` (where `PromptTemplates` lives), a domain-aware `GameContextFormatter` must be implemented in `:usecases` (`com.martorell.albert.basketcoach.usecases.format.GameContextFormatter`), formatting a `List<Game>` into the structured match summary required for AI prompts.
  - *Graceful Degradation in Chat*: If `GameRepository.getPhase1Games()` fails when the coach sends a chat message, `SendChatMessageUseCase` does not abort the user's message; instead, it falls back to passing `gameContext = null` to `ChatRepository.sendMessage(messageText, null)`. This guarantees that chat functionality remains operational even if game dataset loading encounters issues. Conversely, `GenerateInsightsUseCase` and `GetPracticeDrillsUseCase` depend fundamentally on match data; if game loading fails, they propagate the `DomainError` immediately without invoking the AI repository.
  - *Single-Responsibility Interactor Convention*: Each UseCase follows idiomatic Kotlin conventions by implementing a single public `suspend operator fun invoke(...)` function.
  - *Pure JVM Isolation & Test Doubles*: `:usecases` is a 100% pure Kotlin JVM module with zero Android framework dependencies (`android.*`). All unit tests run against clean, lightweight test doubles (fakes) implementing `GameRepository`, `AiAnalysisRepository`, and `ChatRepository`.
* **Necessary Questions:** None — all requirements clarified.

## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Provide a decoupled, testable, and robust set of domain interactors in `:usecases` that encapsulate all business workflows and cross-aggregate orchestration for BasketCoach. Presentation layer ViewModels in `:app` consume these UseCases as their sole entry point to business logic, keeping ViewModels free of data repository coordination and prompt-formatting mechanics.

### Non-Goals
* No repository implementations, DTOs, or network/JSON dependencies (owned exclusively by `:data`).
* No Android framework classes, Jetpack Compose UI composables, or Android ViewModels (owned by `:app`).
* No direct database, Room, or DataStore storage logic.
* No multi-thread chat or conversation branching (constrained by MVP single-thread rule).
* No player-level statistical aggregation (constrained by MVP team-level rule).

### Job Story
When the coach navigates the dashboard, inspects tactical insights, or converses with the AI assistant,
I want the presentation layer to invoke focused, single-responsibility Use Cases that coordinate match data and AI services,
so that business rules, context grounding, and error boundaries remain unified and independent of UI lifecycle or data transport details.

### Acceptance Scenarios

#### Scenario 1: Retrieve All 14 Phase 1 Games
* **Given** a `GetPhase1GamesUseCase` backed by `GameRepository`
* **When** `invoke()` is called
* **Then** it delegates to `GameRepository.getPhase1Games()` and returns `Result.Success(List<Game>)` containing all 14 rounds.

#### Scenario 2: Retrieve a Specific Game by Round Number
* **Given** a `GetGameByRoundUseCase` backed by `GameRepository`
* **When** `invoke(round = 3)` is called
* **Then** it delegates to `GameRepository.getGameByRound(3)` and returns `Result.Success(Game)` with round 3 data.

#### Scenario 3: Request Single Game with Invalid Round
* **Given** a `GetGameByRoundUseCase` backed by `GameRepository`
* **When** `invoke(round = 99)` is called
* **Then** it returns `Result.Error(DomainError.Local.NotFound)`.

#### Scenario 4: Generate Tactical Insights Grounded in Match Context
* **Given** a `GenerateInsightsUseCase` coordinating `GameRepository` and `AiAnalysisRepository`
* **When** `invoke()` is called
* **Then** it fetches games via `GameRepository.getPhase1Games()`, synthesizes match metrics using `GameContextFormatter`, and passes the formatted context string to `AiAnalysisRepository.getInsights(gameContext)`
* **And** returns `Result.Success(List<Insight>)`.

#### Scenario 5: Generate Insights Fails When Games Cannot Be Loaded
* **Given** a `GenerateInsightsUseCase` where `GameRepository.getPhase1Games()` returns `Result.Error(DomainError.Local.NotFound)`
* **When** `invoke()` is called
* **Then** it immediately returns `Result.Error(DomainError.Local.NotFound)` without invoking `AiAnalysisRepository.getInsights(...)`.

#### Scenario 6: Generate Practice Drills Grounded in Match Context
* **Given** a `GetPracticeDrillsUseCase` coordinating `GameRepository` and `AiAnalysisRepository`
* **When** `invoke()` is called
* **Then** it fetches games via `GameRepository.getPhase1Games()`, formats match context, and passes it to `AiAnalysisRepository.getDrills(gameContext)`
* **And** returns `Result.Success(List<Drill>)`.

#### Scenario 7: Retrieve Chat History
* **Given** a `GetChatMessagesUseCase` backed by `ChatRepository`
* **When** `invoke()` is called
* **Then** it delegates to `ChatRepository.getMessages()` and returns `Result.Success(List<ChatMessage>)`.

#### Scenario 8: Send Coach Chat Message with Grounded Match Context
* **Given** a `SendChatMessageUseCase` coordinating `GameRepository` and `ChatRepository`
* **When** `invoke("How can we improve defensive rebounding in Phase 2?")` is called
* **Then** it fetches games via `GameRepository.getPhase1Games()`, formats the match context string, and delegates to `ChatRepository.sendMessage(messageText, gameContext)`
* **And** returns `Result.Success(ChatMessage)` with the AI response.

#### Scenario 9: Send Chat Message with Graceful Fallback When Game Context Fails
* **Given** a `SendChatMessageUseCase` where `GameRepository.getPhase1Games()` returns `Result.Error`
* **When** `invoke("What is a good 2-3 zone defense drill?")` is called
* **Then** it does not abort the message; instead, it invokes `ChatRepository.sendMessage(messageText, gameContext = null)`
* **And** returns `Result.Success(ChatMessage)`.

#### Scenario 10: Reject Blank Chat Message
* **Given** a `SendChatMessageUseCase`
* **When** `invoke("   ")` is called with empty or whitespace-only text
* **Then** it returns `Result.Error(DomainError.Generic("Message text cannot be blank"))` without calling any repository.

#### Scenario 11: Pure Kotlin JVM & Clean Architecture Verification
* **Given** the `:usecases` module build file and source tree
* **When** inspecting dependencies and imports
* **Then** `usecases/build.gradle.kts` depends ONLY on `:domain`, zero imports match `android.*`, and zero imports match `com.martorell.albert.basketcoach.data.*`.

  }

      private val gameRepository: GameRepository,
      private val chatRepository: ChatRepository,
      private val contextFormatter: GameContextFormatter = GameContextFormatter
  ) {

  }

  }
