## 3. Level 2 — Clean Architecture, Governance & Security Audit

### Scope & Architectural Purity
* **Layer Boundaries**: Zero changes to `:domain`, `:data`, or `:usecases`. The feature diff is strictly confined to `:app` and `libs.versions.toml`.

### Compose Navigation Architecture (`compose-navigation-architecture`)
* **Destinations**: Defined in `Destinations.kt` as `@Serializable` objects (`DashboardRoute`, `AnalysisRoute`, `ChatRoute`).
* **Top-Level Navigation**: Uses `TopLevelRoute<T : Any>(@param:StringRes val titleRes: Int, val route: T, val icon: ImageVector)`.
* **State Management**: `BasketCoachAppState` holds `NavHostController`, `CoroutineScope`, and `SnackbarHostState`; owns `NAV_OPTIONS`; determines active route via hierarchy-aware `isRouteSelected` (`currentDestination?.hierarchy?.any { it.hasRoute(route::class) } == true`).
* **State-Preserving Switching**: `navigatePoppingUpToStartDestination` correctly pops up to start destination with `saveState = true`, `launchSingleTop = true`, and `restoreState = true`.
* **Passive Screen Composables**: `DashboardScreen` and `PlaceholderScreen` take zero `NavController` or `AppState` parameters; navigation intents are hoisted.

### Design System Governance (`design-system-governance`)
* **Multipreviews**: All composable previews (`BasketCoachNavRail`, `BasketCoachTopBar`, `DashboardHeroCard`, `KpiCardRow`, `Phase1EvolutionChart`, `Phase1MatchesTable`, `DashboardContent`, `DashboardScreen`) are annotated with both `@BcThemePreview` (Light, Dark, RTL, Large Font) and `@BcDevicePreview` (Tablet Landscape, Phone Landscape).
* **Typographic Hierarchy & Accessibility**: Minimum font size across all composable components is strictly **`12.sp`**. An exhaustive audit confirmed **zero usages** of `10.sp` or `11.sp`.
* **Brand Tokens**: Colors faithfully follow the Pia Sabadell design system (`PiaNavy` `#1D2E54`, `PiaTacticalOrange` `#F15A24`, `PiaSuccessGreen` `#008C45`, `PiaDangerRed` `#D32F2F`, `PiaBackground` `#F5F5F5`, `PiaSurface` `#FFFFFF`).
* **Orientation**: Constrained exclusively to `sensorLandscape` on `MainActivity` in `AndroidManifest.xml`.

### ViewModel & UI State Governance (`viewmodel-architecture-governance`)
* **Strict Default-Free & Non-Nullable Models**: `DashboardUiState.kt` defines 10 immutable UI data classes (`DashboardUiState`, `Phase1SummaryUiModel`, `DashboardKpisUiModel`, `ScoringKpiUiModel`, `ReboundsKpiUiModel`, `ShootingKpiUiModel`, `GameControlKpiUiModel`, `ScoringEvolutionUiModel`, `RoundEvolutionUiModel`, `MatchRowUiModel`).
* **Zero Defaults & Zero Nullables**: All properties have explicit mandatory types without default parameter values (`= ...`) and without nullable types (`?`), complying 100% with fail-fast state modeling governance.

### Security Audit (`android-intent-security`)
* `MainActivity` is the sole registered activity in `AndroidManifest.xml` with `android:exported="true"`, safely guarded by the standard `MAIN`/`LAUNCHER` intent filter.
* Zero Intent redirection vulnerabilities, zero implicit intent broadcasts, and no unvalidated extras.
* `android:supportsRtl="true"` is enabled.
