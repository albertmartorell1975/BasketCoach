## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Provide an immutable, type-safe, pure Kotlin domain model layer for BasketCoach that accurately represents the 14-game Phase 1 dataset, coaches' tactical practice drills, AI analysis findings, single-thread chat messages, and domain repository contracts without any platform or Android framework dependencies.

### Non-Goals
* No JSON parsing or serialization annotations (e.g., Moshi/Gson/Kotlinx Serialization) in the `:domain` module (owned by `feature_002_data_parsing` in `:data`).
* No network API clients or DevExpert prompt generation (owned by `feature_003_devexpert_client` in `:data`).
* No database or Room persistence annotations (owned by persistence features).
* No UI components, Compose elements, or ViewModels (owned by `feature_005_dashboard_ui` and `feature_006_chat_ui` in `:app`).
* No player-level statistics (strict constraint: team-level metrics only).

### Job Story
When a basketball coach reviews Phase 1 performance and interacts with the AI assistant,
I want the application domain layer to represent games, box scores, tactical drills, and chat conversations with clear basketball semantics and calculated outcomes,
so the app can reliably diagnose strengths, weaknesses, and practice recommendations for Phase 2.
