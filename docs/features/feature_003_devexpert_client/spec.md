## 1. Source Feature & Idea Diagnosis
* **`id`:** `feature_003_devexpert_client`
* **`area`:** `data`
* **`depends_on`:** `["feature_001_domain_models"]`
* **`status`:** `in_progress`
* **`module_topology`:** `Layer-Based (:domain, :usecases, :data, :app)`
* **Objective:** Implement the remote AI client and data repository implementations in `:data` for `AiAnalysisRepository` (`getInsights()`, `getDrills()`) and `ChatRepository` (`getMessages()`, `sendMessage()`). The client connects to the **DevExpert Inference API** (`https://inference.devexpert.io/v1/chat/completions`) — using the standard **OpenAI-compatible Chat Completions protocol** — via OkHttp and `kotlinx-serialization-json` to provide batch game analysis grounded in the 14-game Phase 1 dataset for Phase 2 preparation, along with a single-thread AI coaching chat assistant. It also includes seamless zero-code fallback support for Google Gemini's free OpenAI-compatible endpoint (`https://generativelanguage.googleapis.com/v1beta/openai/chat/completions`) for long-term usage after the 60-day DevExpert cohort key expires.
* **Identified Ambiguities / Assumptions:**
  - *AI Provider & OpenAI-Compatible Transport Protocol*: Per the official DevExpert Inference specification (`https://academia.devexpert.io/academy/inference`) and `docs/risks-and-open-questions.md`, DevExpert exposes an OpenAI-compatible REST endpoint (`POST {baseUrl}/chat/completions`) authenticated via `Authorization: Bearer <API_KEY>` with models `"chat"` (daily/fast) and `"chat-pro"` (advanced). Using this standard protocol also allows instant compatibility with Google Gemini's Free Tier OpenAI-compatible endpoint (`https://generativelanguage.googleapis.com/v1beta/openai`, model `"gemini-2.5-flash"`) simply by switching config values.
  - *Network Abstraction*: An interface `DevExpertApiClient` abstracts the remote HTTP transport from repository implementations. This allows `AiAnalysisRepositoryImpl` and `ChatRepositoryImpl` to remain testable in isolation using mock/fake clients, while `DevExpertApiClientImpl` is independently tested with `MockWebServer` (requiring no real API key for unit testing).
  - *Prompt Grounding & Context (Both Analysis & Chat)*: Both tactical analysis (`AiAnalysisRepositoryImpl`) and conversational chat (`ChatRepositoryImpl`) inject `GameRepository` (from `feature_002_data_parsing`) to summarize team box scores (3 wins, 11 losses, AST/TO ratios, rebounding deficits, personal fouls) and instruct the model on the explicit Phase 2 goal: eliminate Phase 1 weaknesses and reinforce Phase 1 winning strengths.
  - *Single-Call Shared Cache with `Mutex` (`AiAnalysisRepositoryImpl`)*: Because `AiAnalysisResponseDto` returns both `insights` and `drills` in a single structured JSON payload, `AiAnalysisRepositoryImpl` uses a `kotlinx.coroutines.sync.Mutex` so that concurrent or sequential calls to `getInsights()` and `getDrills()` execute **only 1 HTTP request**, populating both `cachedInsights` and `cachedDrills` simultaneously and preserving weekly API quota.
  - *Structured Output Parsing & Language*: The analysis prompt instructs the model to keep all JSON property keys and `InsightCategory` enum values (`OFFENSE`, `DEFENSE`, `SYNERGY`, `GENERAL`) strictly in English while generating human-readable content, and instructs the chat assistant to reply in the language used by the coach. `DevExpertApiClientImpl` strips optional Markdown code fences (` ```json ... ``` `) if returned by the LLM before deserializing into `AiAnalysisResponseDto`, and `AiAnalysisMapper` converts DTOs to pure domain entities.
  - *Single-Thread Chat State*: `ChatRepositoryImpl` maintains the active conversation thread in memory (`mutableListOf<ChatMessage>`), matching the MVP constraint (`CONSTRAINTS.md`: "Single Thread Chat"). It appends coach prompts, includes Phase 1 game context and conversation history mapped to `system` / `user` / `assistant` roles in subsequent requests, and appends AI responses.
  - *API Key & Dual-Provider Governance*: `DevExpertConfig` accepts `apiKey`, `baseUrl`, and `model` via constructor (so `:app` can inject from `BuildConfig`) and provides `fromEnvironment()` with layered resolution:
    1. **Environment / System Property / `local.properties` (`DEVEXPERT_API_KEY`)**: Resolves to `baseUrl = "https://inference.devexpert.io/v1"`, `model = "chat"`.
    2. **Fallback (`GEMINI_API_KEY`)**: If `DEVEXPERT_API_KEY` is absent and `GEMINI_API_KEY` is present in env/property/`local.properties`, resolves to `baseUrl = "https://generativelanguage.googleapis.com/v1beta/openai"`, `model = "gemini-2.5-flash"`.
    3. **Missing / Blank Key**: If no key is configured, network requests return `Result.Error(DomainError.Network.Unauthorized)` gracefully without crashing.
  - *Typed Error Mapping*: In alignment with `repository-pattern-governance`, all network exceptions (`SocketTimeoutException`, `IOException`, HTTP 401/403, 5xx, JSON parsing errors) are caught using `safeCall` (re-throwing `CancellationException`) and mapped into typed `DomainError` instances. No framework exceptions leak to `:domain`.

## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Provide a production-grade, testable remote client and repository implementation in `:data` that connects BasketCoach to the DevExpert Inference API (and Gemini Free Tier fallback) via the standard OpenAI-compatible `/chat/completions` endpoint. The solution enables automated tactical performance diagnosis (strengths, weaknesses, and drills) grounded in the Phase 1 dataset to prepare for Phase 2, and powers a single-thread conversational chat assistant with full error handling and 100% offline/mockable JVM testability.

### Non-Goals
* No UI composables, ViewModels, or screen layouts (owned by `feature_005_dashboard_ui` and `feature_006_chat_ui` in `:app`).
* No UseCase interactors (owned by `feature_004_usecases`).
* No Room or SQLite persistence for chat messages (MVP constraint: single-thread in-memory session).
* No individual player statistics (MVP constraint: team-level metrics only).
* No multi-thread chat or conversation history persistence across app restarts.
* No direct Android SDK framework dependencies in `:data` (remains pure Kotlin JVM).

### Job Story
When a basketball coach reviews Phase 1 performance or asks tactical questions,
I want the `:data` layer to securely communicate with the DevExpert Inference service (or Gemini Free Tier fallback) using grounded match context and structured prompt templates over `/chat/completions`,
so the application can deliver actionable tactical insights, practice drills, and chat responses without crashes, vendor lock-in, or unhandled network exceptions.

### Acceptance Scenarios

#### Scenario 1: Generate Tactical Insights Grounded in Phase 1 Matches & Shared Cache
* **Given** a configured `AiAnalysisRepositoryImpl` with access to Phase 1 games from `GameRepository`
* **When** `getInsights()` is invoked
* **Then** it dispatches a `POST /chat/completions` request with `Authorization: Bearer <apiKey>`, `model`, and system/user messages containing the 14-game summary and Phase 2 objectives
* **And** returns `Result.Success` containing a list of `Insight` domain entities categorized into `OFFENSE`, `DEFENSE`, `SYNERGY`, or `GENERAL` with valid `relatedGameRounds`
* **And** subsequent calls to `getInsights()` or `getDrills()` return cached results without repeating the network call.

#### Scenario 2: Generate Recommended Practice Drills for Phase 2
* **Given** a configured `AiAnalysisRepositoryImpl`
* **When** `getDrills()` is invoked
* **Then** it returns `Result.Success` containing a list of `Drill` domain entities
* **And** each drill contains an `id`, `name`, `objective`, `focusArea`, and step-by-step `instructions`.

#### Scenario 3: Single-Thread Chat Conversation Progression with Game Context
* **Given** an initialized `ChatRepositoryImpl` with an empty message thread and access to `GameRepository`
* **When** `sendMessage("How can we improve defensive rebounding in Phase 2?")` is invoked
* **Then** the coach's message is immediately appended to the in-memory conversation thread with `MessageSender.COACH`
* **And** the request to `/chat/completions` includes the Phase 1 14-game context and returns an AI coaching response in `choices[0].message.content`
* **And** the AI message is appended to the thread with `MessageSender.AI` and returned as `Result.Success(aiMessage)`
* **And** `getMessages()` returns both messages in ascending chronological order.

#### Scenario 4: Resilient Network Failure & Timeout Handling
* **Given** a simulated network connection timeout or socket failure during an API call
* **When** `getInsights()` or `sendMessage(...)` is invoked
* **Then** the call does not throw an uncaught exception
* **And** returns `Result.Error(DomainError.Network.Timeout)` or `Result.Error(DomainError.Network.NoInternet)`.

#### Scenario 5: Unauthorized Access & Missing API Key
* **Given** `DevExpertConfig` configured with an empty or invalid API key
* **When** an AI request is executed against the API
* **Then** the repository returns `Result.Error(DomainError.Network.Unauthorized)` without crashing.

#### Scenario 6: Malformed AI JSON Response Recovery
* **Given** the remote API returns an unexpected or malformed response body that cannot be parsed into the expected DTO schema
* **When** `getInsights()` processes the payload
* **Then** the repository returns `Result.Error` with `DomainError.Generic` detailing the parsing issue.

### API Design
* **Endpoint Contract (OpenAI-Compatible Chat Completions)**:
  - Method & Path: `POST {baseUrl}/chat/completions`
  - Default DevExpert Base URL: `https://inference.devexpert.io/v1`
  - Default DevExpert Model: `"chat"` (also supports `"chat-pro"`)
  - Fallback Gemini Base URL: `https://generativelanguage.googleapis.com/v1beta/openai`
  - Fallback Gemini Model: `"gemini-2.5-flash"`
  - Request Headers:
    - `Content-Type: application/json`
    - `Authorization: Bearer {apiKey}`
  - Request Body Schema:
    ```json
    {
      "model": "chat",
      "messages": [
        { "role": "system", "content": "..." },
        { "role": "user", "content": "..." }
      ]
    }
    ```
  - Response Body Schema:
    ```json
    {
      "choices": [
        {
          "message": {
            "role": "assistant",
            "content": "..."
          }
        }
      ]
    }
    ```
* **Client Interface**:
  ```kotlin
  interface DevExpertApiClient {
      suspend fun generateAnalysis(gameContext: String): Result<AiAnalysisResponseDto, DomainError>
      suspend fun generateChatResponse(
          conversationHistory: List<ChatMessage>,
          newPrompt: String,
          gameContext: String? = null
      ): Result<String, DomainError>
  }
  ```
* **Error Mapping Protocol**:
  - `SocketTimeoutException` -> `DomainError.Network.Timeout`
  - `UnknownHostException` / `ConnectException` / `IOException` -> `DomainError.Network.NoInternet`
  - HTTP 401 / 403 -> `DomainError.Network.Unauthorized`
  - HTTP 500..599 -> `DomainError.Network.ServerError(code, message)`
  - Blank API key -> `DomainError.Network.Unauthorized`
  - JSON Deserialization Exception -> `DomainError.Generic("Failed to parse AI response", cause)`

### Persistence
* Thread-safe in-memory caching for batch analysis (`Mutex` + `cachedInsights: List<Insight>?`, `cachedDrills: List<Drill>?` in `AiAnalysisRepositoryImpl`).
* Thread-safe in-memory storage for chat (`Mutex` + `messages = mutableListOf<ChatMessage>()` in `ChatRepositoryImpl`).
* No Room or SQLite database required in this feature slice.
