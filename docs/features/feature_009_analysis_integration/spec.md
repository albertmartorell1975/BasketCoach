## 1. Source Feature & Idea Diagnosis
* **`id`:** `feature_009_analysis_integration`
* **`area`:** `app`
* **`depends_on`:** `["feature_004_usecases", "feature_006_analysis_ui"]`
* **`status`:** `in_progress`
* **`module_topology`:** `Layer-Based (:domain, :usecases, :data, :app)`
* **Objective:** Connect the Tablet Landscape Analysis screen (`AnalysisScreen`, built in `feature_006_analysis_ui`) to authentic Phase 1 game data and AI-generated tactical insights loaded asynchronously via `GetPhase1GamesUseCase` and `GenerateInsightsUseCase`. Extend the Hilt Dependency Injection graph across `:usecases`, `:data`, and `:app` to provide `AiClientConfig`, `AiRemoteDataSource`, `AiAnalysisLocalDataSource`, and `AiAnalysisRepository`; introduce `AnalysisViewModel` adhering strictly to the MVVM Passive Initialization Mandate (`loadAnalysis()`) and the Hybrid UI State Pattern (`AnalysisUiState` wrapping `AnalysisUiContent.Loading`, `Success`, `Error(val error: DomainError)` with `isRefreshing` overlay); implement `AnalysisUiMapper` as the sole authoritative transformation engine mapping `List<Game>` and `List<Insight>` into `AnalysisUiContent.Success` (and handling client-side tab filtering); and provide resilient loading and localized error recovery (`UiText` + `toAnalysisUiText()`) with retry capability.
* **Identified Ambiguities / Assumptions:**
  - *Hilt DI Expansion & Strict Module Isolation (`hilt/SKILL.md`)*: Per `hilt/SKILL.md`, abstract `@Binds` modules and `object` `@Provides` modules must never be mixed in the same class.
    - `:usecases` remains 100% pure Kotlin JVM (zero `android.*` and zero Hilt plugins), annotating `GenerateInsightsUseCase` with JSR-330 `@Inject constructor`.
    - `:data` remains 100% pure Kotlin JVM, adding JSR-330 `@Inject` constructors to `AiAnalysisLocalDataSourceImpl`, `AiRemoteDataSourceImpl` (via secondary `@Inject constructor(config: AiClientConfig)` preserving default `OkHttpClient` and `Json` parameters for existing unit tests), and `AiAnalysisRepositoryImpl`.
    - `:app` adds `NetworkModule` (`@Module @InstallIn(SingletonComponent::class) object NetworkModule`) providing `@Provides @Singleton fun provideAiClientConfig(): AiClientConfig` (reading `BuildConfig.DEVEXPERT_API_KEY` / `BuildConfig.GEMINI_API_KEY` injected at Gradle build time from `local.properties` / environment variables, and falling back to `AiClientConfig.fromEnvironment()`), extends `DataSourceModule` (`@Binds @Singleton` for `AiAnalysisLocalDataSource` and `AiRemoteDataSource`), and extends `RepositoryModule` (`@Binds @Singleton` for `AiAnalysisRepository`).
    - `:app/src/main/AndroidManifest.xml` declares `<uses-permission android:name="android.permission.INTERNET" />` so OkHttp network requests can execute on Android devices/emulators.
  - *Passive Initialization Mandate (`viewmodel-architecture-governance`)*: `AnalysisViewModel` MUST NOT launch coroutines or start data collection in its constructor or `init` block. Its initial state defaults passively to `AnalysisUiState(content = AnalysisUiContent.Loading, isRefreshing = false)`. Data loading is explicitly triggered from `AnalysisScreen` via `LaunchedEffect(Unit) { viewModel.loadAnalysis() }`.
  - *Hybrid UI State & In-Memory Tab Filtering*: `AnalysisUiState(val content: AnalysisUiContent, val isRefreshing: Boolean)` wraps `sealed interface AnalysisUiContent` (`Loading`, `Success`, `Error(val error: DomainError)`). `AnalysisUiContent.Success` holds `summary: Phase1SummaryUiModel`, `selectedFilter: InsightFilterTab`, `totalCount: Int`, `strengthsCount: Int`, `improvementsCount: Int`, `allInsights: List<InsightCardUiModel>`, and `displayedInsights: List<InsightCardUiModel>`. Selecting a filter tab via `viewModel.onFilterSelected(tab)` synchronously filters `allInsights` in memory via `AnalysisUiMapper.filterInsights(...)` and updates `_uiState` atomically via `MutableStateFlow.update { ... }` without triggering redundant network calls.
  - *Strict Default-Free & Non-Nullable UI Models (Constraint #17) & Zero Hardcoded Strings (Constraint #18)*:
    - All properties in `AnalysisUiState`, `AnalysisUiContent.Success`, and `InsightCardUiModel` are strictly non-nullable with zero default parameter values.
    - To eliminate hardcoded language literals from mappers (Constraint #18), `InsightCardUiModel` replaces `categoryBadgeText: String` with `@param:StringRes val categoryBadgeRes: Int` (`R.string.analysis_badge_strength` for `InsightType.STRENGTH`, `R.string.analysis_badge_improvement` for `InsightType.IMPROVEMENT`), resolved in `InsightCardHeader` via `stringResource(card.categoryBadgeRes)`. Similarly, `AnalysisHeroCard` replaces inline Catalan literals with `stringResource(R.string.hero_competitive_balance, summary.wins, summary.losses)` and `stringResource(R.string.hero_win_pct, summary.winPercentage)`.
    - `AnalysisViewModel` exposes raw `DomainError` in `AnalysisUiContent.Error(error)` with zero `R.string` imports. Error translation occurs exclusively in the UI layer via `fun DomainError.toAnalysisUiText(): UiText`.
  - *Pragmatic High-Value Testing & Strict Test Budget (Constraint #18)*:
    - Pure JVM unit tests only; zero Robolectric UI tests (`*ScreenTest`).
    - Strict budget capped at 1 to 3 `@Test` methods per test class, and 4 `@Test` methods total across the feature slice: `AnalysisUiMapperTest` (2 tests verifying domain-to-UI mapping, summary math, category filtering, and empty-games guard) and `AnalysisViewModelTest` (2 tests verifying passive initialization, `loadAnalysis()` transition to `Success`, in-memory filter switching, and `Error` state transition + retry recovery).
* **Necessary Questions:** None — all architectural requirements and constraints are clear and unambiguous.

## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Replace static preview data on the Tablet Landscape Analysis (`Anàlisi`) screen with authentic Phase 1 match summary metrics and AI-generated tactical insights loaded asynchronously from `GetPhase1GamesUseCase` and `GenerateInsightsUseCase`. Deliver a production-grade MVVM integration with Hilt DI, passive ViewModel initialization, atomic UDF state updates, instant client-side segmented tab filtering (`Tots`, `Fortaleses`, `Àrees de Millora`), localized error feedback (`UiText`), and retry recovery.

### Non-Goals
* No modification to conversational Chat ViewModel or live chat message sending (owned by `feature_010_chat_integration`).
* No Room database schema changes (AI insights and drills use the existing thread-safe `Mutex` in-memory `AiAnalysisLocalDataSource` cache).
* No individual player statistics (MVP constraint: team-level and opponent-level metrics only).
* No smartphone or portrait layouts (strict Tablet Landscape `1280x800dp`).

### Job Story
When Coach Jordi navigates to the Anàlisi screen on his tablet,
I want the application to asynchronously fetch the Phase 1 match baseline and AI-generated tactical insights via `GetPhase1GamesUseCase` and `GenerateInsightsUseCase`,
so that Coach Jordi can inspect authentic team strengths and vulnerabilities, filter by tactical category, recover from network errors via retry, and jump directly to the Socratic Chat with grounded prompts.

### Acceptance Scenarios

#### Scenario 1: Happy Path — Loading and Rendering Real Phase 1 Summary & AI Insights
* **Given** functional `GetPhase1GamesUseCase` (returning the 14 Phase 1 games) and `GenerateInsightsUseCase` (returning tactical `Insight` entities)
* **When** Coach Jordi navigates to the Analysis screen and `loadAnalysis()` executes
* **Then** `AnalysisViewModel` transitions from `AnalysisUiContent.Loading` to `AnalysisUiContent.Success`
* **And** `AnalysisScreen` renders `AnalysisHeroCard` with the authentic 3V-11D (21.4%) Phase 1 summary, accurate tab counts (`Tots`, `Fortaleses`, `Àrees de Millora`), and `InsightCardGrid` displaying the mapped `InsightCardUiModel` cards.

#### Scenario 2: Passive Initialization Mandate Compliance
* **Given** `AnalysisViewModel` is instantiated
* **When** inspecting `uiState.value` before any UI-driven `LaunchedEffect` or user action
* **Then** no coroutines or repository queries have been launched in constructor or `init`
* **And** `uiState.value.content` is strictly `AnalysisUiContent.Loading` and `uiState.value.isRefreshing` is `false`.

#### Scenario 3: In-Memory Segmented Tab Filtering on Loaded Insights
* **Given** `AnalysisViewModel` is in `AnalysisUiContent.Success` with both `InsightType.STRENGTH` and `InsightType.IMPROVEMENT` insights loaded and `selectedFilter == InsightFilterTab.ALL`
* **When** Coach Jordi taps "Fortaleses" (`onFilterSelected(InsightFilterTab.STRENGTHS)`)
* **Then** `AnalysisViewModel` atomically updates `selectedFilter` to `InsightFilterTab.STRENGTHS` and `displayedInsights` to only `STRENGTH` cards without invoking `GenerateInsightsUseCase` again
* **When** Coach Jordi taps "Àrees de Millora" (`onFilterSelected(InsightFilterTab.IMPROVEMENTS)`)
* **Then** `displayedInsights` updates immediately to only `IMPROVEMENT` cards, each exposing `canExploreChat == true` when `exploreChatPrompt` is non-blank.

#### Scenario 4: Network / Local Error State & Retry Recovery
* **Given** `GenerateInsightsUseCase` returns `Result.Error(DomainError.Network.NoInternet)` (or `Unauthorized` / `Timeout` / `Local.NotFound`)
* **When** `loadAnalysis()` executes
* **Then** `AnalysisViewModel` emits `AnalysisUiContent.Error(error = DomainError.Network.NoInternet)` with `isRefreshing = false`
* **And** `AnalysisScreen` displays `AnalysisErrorView` with the localized error description and a "Reintentar" button
* **When** Coach Jordi taps "Reintentar" and the use cases return `Result.Success`
* **Then** `AnalysisViewModel` re-executes the load and transitions to `AnalysisUiContent.Success`.

#### Scenario 5: Idempotent Concurrency Guarding
* **Given** `AnalysisViewModel` is currently executing an analysis load (`isRefreshing == true`)
* **When** a duplicate `loadAnalysis()` call is triggered concurrently
* **Then** the duplicate invocation is ignored without launching a second coroutine or duplicate API request.

#### Scenario 6: Pure Kotlin JVM Layer Boundaries & Bilingual Resource Parity
* **Given** constructor injection across `:usecases` and `:data` and localized UI error/loading strings in `:app`
* **When** inspecting module dependencies and string dictionaries
* **Then** `:domain` and `:usecases` contain zero `android.*` imports, `AnalysisViewModel` contains zero `R.string` imports, and `res/values/strings.xml` (Catalan) and `res/values-es/strings.xml` (Spanish) maintain 100% key parity with all typography >= `12.sp`.

## 4. Android Layer Breakdown

### UI/UX & Visual Assets
* **UI Involved:** Yes.
* **Design Source:** `DESIGN.md` / `docs/ui/screens/analisis_landscape/`.
* **States & Navigation:**
  - *Loading State (`AnalysisLoadingView`)*: Centered `48.dp` `CircularProgressIndicator` in `PiaNavy` with `14.sp` `PiaTextMuted` localized message (`R.string.analysis_loading`).
  - *Error State (`AnalysisErrorView`)*: Centered `Card` (`max = 480.dp`, `RoundedCornerShape(12.dp)`, `PiaDangerRed` border) displaying `R.string.analysis_error_title` (`16.sp` bold), localized `UiText` message (`13.sp`), and `PiaNavy` retry button (`R.string.analysis_error_retry`, `13.sp`).
  - *Success State (`AnalysisContent`)*: Vertically scrollable layout displaying `AnalysisHeroCard` (3V-11D, 21.4%, segmented filter tabs) and `InsightCardGrid` (3-column grid of tactical strength and improvement cards, with empty category fallback `R.string.analysis_empty_state`).
  - *Navigation*: `Navigation.kt` routes `AnalysisRoute` to `AnalysisScreen(onNavigateToChat = { prompt -> appState.navigateToChat(prompt) })`, keeping `AnalysisScreen` 100% decoupled from `NavController`.
* **Graphic Assets Conversion:** N/A — No new PNG/JPEG assets in `docs/features/feature_009_analysis_integration/ui/resources/`.

### API Design
Uses existing `AiRemoteDataSource` (`POST {baseUrl}/chat/completions`) implemented in `:data` (`feature_003_devexpert_client` / `feature_006_analysis_ui`). `NetworkModule` in `:app` resolves `AiClientConfig` from `BuildConfig.DEVEXPERT_API_KEY` / `BuildConfig.GEMINI_API_KEY` (populated from `local.properties` or environment variables at build time) with fallback to `AiClientConfig.fromEnvironment()`.

### Persistence
No Room database changes required. Uses the existing thread-safe in-memory `AiAnalysisLocalDataSourceImpl` (`Mutex`-guarded SSOT cache) bound as a `@Singleton` in `DataSourceModule` so generated insights and drills remain cached across tab switches during the session.
