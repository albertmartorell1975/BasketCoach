## 1. Source Feature & Idea Diagnosis
* **`id`:** `feature_010_chat_integration`
* **`area`:** `app` (with `:data` and `:usecases` integration)
* **`depends_on`:** `["feature_004_usecases", "feature_007_chat_ui"]`
* **`status`:** `in_progress`
* **`module_topology`:** `Layer-Based (:domain, :usecases, :data, :app)`
* **Objective:** Connect the Tablet Landscape Single-Thread Chat screen (`ChatScreen`, built in `feature_007_chat_ui`) to the live DevExpert AI inference pipeline and in-memory single-thread repository via `GetPhase1GamesUseCase`, `GetChatMessagesUseCase`, and `SendChatMessageUseCase`. Incorporate a **2-step AI Guardrail Pipeline** in `:data`:
  1. **DevExpert Mode**: Uses **DevExpert Jev Decisions (`POST /v1/decisions` with `model = "jev"`)** to pre-classify each coach prompt (`basketball_relevant` vs `off_topic`) before invoking the generative `chat` model with the 14-game Phase 1 dataset.
  2. **Gemini Fallback Mode**: When running on Google Gemini Free Tier (`GEMINI_API_KEY`), executes a lightweight zero-shot classification JSON call (`temperature = 0.0`, zero match history tokens) to `/chat/completions` returning `choice: "basketball_relevant" | "off_topic"`.
  When off-topic, short-circuits with a polite tactical refusal bubble without wasting generative tokens on the 14-game context. Complete the Hilt Dependency Injection graph across `:usecases`, `:data`, and `:app`; implement `ChatViewModel` adhering strictly to the Passive Initialization Mandate (`loadChat(initialPrompt)`) and Hybrid UI State Pattern (`ChatUiState` wrapping `ChatUiContent.Loading`, `Success`, `Error(val error: DomainError)` with `isSending` overlay); implement `ChatUiMapper` without hardcoded strings; and provide localized error recovery (`toChatUiText()`).
* **Identified Ambiguities / Assumptions:**
  - *Pre-Classification Guardrail via DevExpert Jev Decisions (`POST {baseUrl}/decisions`) & Gemini Fallback*:
    - Before dispatching the heavy `POST {baseUrl}/chat/completions` request containing the 14-game Phase 1 summary and conversation history, `AiRemoteDataSource.isPromptBasketballRelevant(prompt: String, lastAssistantMessage: String?): Boolean` evaluates the query:
      - If `config.baseUrl` contains `"devexpert.io"`: sends a classification request to `POST {baseUrl}/decisions` using `model = DevExpertConfig.MODEL_JEV` (`"jev"`), with `state` containing `app_domain`, `last_assistant_message`, and `coach_message`, and the `"domain_relevance"` question of `type = "choice"` (`"basketball_relevant"` vs `"off_topic"`).
      - If using the Gemini fallback: sends a compact classification prompt to `/chat/completions` asking for `{"choice": "basketball_relevant" | "off_topic"}` with `temperature = 0.0` and without game context.
    - **Short-Circuit Behavior**: When `isPromptBasketballRelevant` returns `false` (`"off_topic"`), `ChatRepositoryImpl.sendMessage(...)` short-circuits **without calling `generateChatResponse`**, saves a polite localized AI refusal message (`PromptTemplates.buildOffTopicRejectionMessage()`) to `ChatLocalDataSource` as `MessageSender.AI`, and returns `Result.Success(aiMessage)`.
    - **Defense-in-Depth System Prompt**: `PromptTemplates.buildChatSystemPromptBase` also includes an explicit `STRICT DOMAIN GUARDRAIL` clause.
  - *Hilt DI Completion (`hilt/SKILL.md`)*:
    - `:usecases`: JSR-330 `@Inject constructor` on `GetChatMessagesUseCase`, `SendChatMessageUseCase`, and `GetPracticeDrillsUseCase`.
    - `:data`: `@Inject constructor()` on `ChatLocalDataSourceImpl` and secondary `@Inject constructor(remoteDataSource: AiRemoteDataSource, localDataSource: ChatLocalDataSource)` on `ChatRepositoryImpl`.
    - `:app`: bind `ChatLocalDataSourceImpl` to `ChatLocalDataSource` in `DataSourceModule` and `ChatRepositoryImpl` to `ChatRepository` in `RepositoryModule` using `@Binds @Singleton`.
  - *Passive Initialization Mandate & 'Explorar al Xat' Hand-off (`viewmodel-architecture-governance`)*:
    - `ChatViewModel` performs zero work in `init`. Initial state is `ChatUiState(content = ChatUiContent.Loading, isSending = false)`.
    - `ChatScreen` triggers `LaunchedEffect(initialPrompt) { viewModel.loadChat(initialPrompt) }`.
    - When `initialPrompt` is non-blank (via `'Explorar al Xat'`), sets `leftPaneMode = ChatLeftPaneMode.DIAGNOSTIC_EVIDENCE` and automatically dispatches `sendMessage(initialPrompt)`.
  - *Single Thread Chat (Constraint #6)*:
    - `ChatLocalDataSourceImpl` is scoped as `@Singleton` in `DataSourceModule`.
  - *Strict Default-Free & Non-Nullable UI Models (Constraint #17) & Zero Hardcoded Strings (Constraint #18)*:
    - `ChatUiState(val content: ChatUiContent, val isSending: Boolean)` with `ChatUiContent.Loading`, `Success`, `Error(val error: DomainError)`.
    - `ChatMessageUiModel` uses `@param:StringRes val senderNameRes: Int` and `@param:StringRes val senderRoleRes: Int`.
    - `ChatMetaHeaderUiModel` holds typed metrics and string resource IDs.
    - `DomainError.toChatUiText(): UiText` translates domain errors to localized strings.
  - *Pragmatic High-Value Testing & Strict Test Budget (Constraint #18)*:
    - Pure JVM unit tests only; zero Robolectric UI tests.
    - Strict budget of **6 new `@Test` methods total across all layers**:
      - `AiRemoteDataSourceTest` (`:data`): 1 test verifying `POST /decisions` with `model = "jev"`.
      - `ChatRepositoryImplTest` (`:data`): 1 test verifying off-topic prompt short-circuiting.
      - `ChatUiMapperTest` (`:app`): 2 tests verifying mapping and empty-games guard.
      - `ChatViewModelTest` (`:app`): 2 tests verifying passive initialization + explore prompt dispatch and error transition + retry recovery.
