## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Prevent redundant Phase 1 game reloads when navigating back to an already-loaded Dashboard, give Coach Jordi immediate `Loading` feedback when retrying from an `Error` state, and render a non-destructive refresh overlay indicator over `DashboardContent` whenever `DashboardUiContent.Success` is actively refreshing (`isRefreshing == true`).

### Non-Goals
* No changes to `:domain`, `:usecases`, `:data`, Hilt modules, or Gradle build scripts (`*.gradle.kts`).
* No changes to `DashboardUiState.kt`, `DashboardUiMapper.kt`, `Navigation.kt`, or string resources.
* No new unit test files or Robolectric Compose UI tests (`*ScreenTest`).

### Job Story
When Coach Jordi navigates away from the Dashboard and returns, retries after an error, or triggers a forced reload,
I want `DashboardViewModel` and `DashboardScreen` to avoid redundant reloads on `Success`, transition immediately to `Loading` on error retry, and show a subtle refresh overlay during forced refreshes,
so that navigation feels instant and loading feedback is always clear and consistent with the Analysis screen.

### Acceptance Scenarios

#### Scenario 1: Re-Entry Guard Prevents Redundant Reload on `Success`
* **Given** `DashboardViewModel` has already completed loading and `uiState.value.content` is `DashboardUiContent.Success` with `isRefreshing == false`
* **When** `loadDashboard()` is invoked again with default `forceRefresh = false` (e.g. on composition re-entry via `LaunchedEffect(Unit)`)
* **Then** `DashboardViewModel` returns immediately without mutating `uiState` or invoking `GetPhase1GamesUseCase` / `GameRepository` again.

#### Scenario 2: Explicit `forceRefresh = true` Bypasses Guard & Renders Refresh Overlay
* **Given** `DashboardViewModel` is in `DashboardUiContent.Success` with `isRefreshing == false`
* **When** `loadDashboard(forceRefresh = true)` is called
* **Then** `_uiState` synchronously updates to keep `currentState.content` (`DashboardUiContent.Success`) while setting `isRefreshing = true`
* **And** stateless `DashboardScreen` renders an overlay `Box` with `Modifier.fillMaxSize().background(Color.Black.copy(alpha = 0.15f))` and centered `CircularProgressIndicator(color = PiaNavy)` over `DashboardContent`
* **And** once `GetPhase1GamesUseCase` completes, `isRefreshing` resets to `false`.

#### Scenario 3: Immediate `Loading` Transition on Retry From `Error`
* **Given** `DashboardViewModel` is in `DashboardUiContent.Error` with `isRefreshing == false`
* **When** Coach Jordi triggers retry (`onRetry` -> `viewModel.loadDashboard(forceRefresh = true)`, or `loadDashboard()` is called)
* **Then** before the coroutine completes, `uiState.value.content` immediately transitions to `DashboardUiContent.Loading` and `uiState.value.isRefreshing` becomes `true`
* **And** upon subsequent `Result.Success` from `GetPhase1GamesUseCase`, state transitions to `DashboardUiContent.Success` with `isRefreshing == false`.

#### Scenario 4: In-Flight Concurrency Guard Remains Idempotent
* **Given** `DashboardViewModel` is currently loading or refreshing (`isRefreshing == true`)
* **When** `loadDashboard()` or `loadDashboard(forceRefresh = true)` is invoked concurrently
* **Then** the duplicate call returns immediately without launching a second coroutine or repository query.
