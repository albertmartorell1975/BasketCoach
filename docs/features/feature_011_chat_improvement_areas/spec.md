* **`depends_on`:** `["feature_009_analysis_integration", "feature_010_chat_integration"]`

* **`module_topology`:** `Layer-Based (:domain, :usecases, :data, :app)`
* **Objective:** Synchronize the Tablet Landscape Chat left workbench pane (`ChatLeftPane` / `ChatTopicList`) with the real AI-generated tactical Improvement Areas (`InsightType.IMPROVEMENT`) loaded via `GenerateInsightsUseCase` (sharing the `@Singleton` `AiAnalysisLocalDataSource` cache with `AnalysisScreen`, or fetching from the AI API if the user opens Chat directly). Remove the `ChatLeftPaneMode.DIAGNOSTIC_EVIDENCE` transition so the left pane permanently displays the list of Improvement Areas plus the final `CONSULTA LLIURE` ("Open Inquiry") card. Scope conversation threads by `topicId: String` across `:domain`, `:data`, `:usecases`, and `:app` so clicking any Improvement Area (or Open Inquiry) in the left pane highlights it as active and switches the right pane (`ChatRightPane`) to display and continue that specific topic's conversation thread.
* **Identified Ambiguities / Assumptions:**
  - *Shared AI Insights Cache & Direct Chat Navigation*:
    - `ChatViewModel` injects `GenerateInsightsUseCase` in addition to `GetPhase1GamesUseCase`, `GetChatMessagesUseCase`, `SendChatMessageUseCase`, and `ChatUiMapper`.
    - Because `AiAnalysisLocalDataSource` is bound as `@Singleton` in `DataSourceModule`, if Coach Jordi visits `Anàlisi` first, `generateInsightsUseCase()` resolves synchronously from the in-memory `Mutex` cache with zero duplicate network calls. If Coach Jordi navigates directly to `Chat` first, `generateInsightsUseCase()` fetches the insights from the AI service and populates the shared cache.
  - *Permanent Left Pane Topic List (Removal of `DIAGNOSTIC_EVIDENCE` Mode Switching)*:
    - `ChatUiContent.Success` removes `leftPaneMode: ChatLeftPaneMode` and `diagnosticEvidence: ChatDiagnosticEvidenceUiModel`, and changes `activeTopicId` from `ChatTopicId` to `String`.
    - `ChatLeftPane` permanently renders `ChatTopicList` without `AnimatedContent` mode switching to `ChatDiagnosticEvidenceView`.
    - `ChatTopicList` makes the topic cards column vertically scrollable (`verticalScroll(rememberScrollState())`) so any number of AI-generated improvement areas plus the `CONSULTA LLIURE` card fit cleanly on the `1280x800dp` tablet display.
  - *Topic-Scoped Conversation Threads (`topicId: String`)*:
    - `:domain` defines `const val OPEN_INQUIRY_TOPIC_ID = "open_inquiry"` in `ChatRepository.kt` and adds `topicId: String = OPEN_INQUIRY_TOPIC_ID` to `ChatRepository.getMessages(topicId)` and `ChatRepository.sendMessage(messageText, games, topicId)`.
    - `:data` updates `ChatLocalDataSource` and `ChatLocalDataSourceImpl` to store messages in a `Mutex`-protected `mutableMapOf<String, MutableList<ChatMessage>>()` keyed by `topicId`. `ChatRepositoryImpl` scopes message persistence and conversation history grounding to the requested `topicId`.
    - `:usecases` updates `GetChatMessagesUseCase.invoke(topicId: String = OPEN_INQUIRY_TOPIC_ID)` and `SendChatMessageUseCase.invoke(messageText: String, topicId: String = OPEN_INQUIRY_TOPIC_ID)`.
  - *'Explorar al Xat' Hand-off & Topic Matching*:
    - When `loadChat(initialPrompt)` is invoked with a non-blank `initialPrompt` from `AnalysisScreen`, `ChatViewModel` matches `initialPrompt` against the loaded `InsightType.IMPROVEMENT` insights (`insight.exploreChatPrompt == initialPrompt || insight.id == initialPrompt`) to select the matching `insight.id` as `activeTopicId`.
    - If `initialPrompt` is non-blank and has not yet been processed (`!initialPromptProcessed`) and the target topic's message thread is empty, `ChatViewModel` automatically dispatches `sendMessage(initialPrompt)` on that `activeTopicId`.
  - *Strict Default-Free & Non-Nullable UI Models (Constraint #17) & Zero Hardcoded Strings (Constraint #18)*:
    - `ChatTopicCardUiModel` uses `val id: String`, `val badgeText: UiText`, `val isPriority: Boolean`, `val isOpenInquiry: Boolean`, `val title: UiText`, `val description: UiText`, `val statusPill: UiText`, `val hasMetricPill: Boolean`, `val metricPill: UiText`, `val metricPillIsNegative: Boolean`, and `val exploreChatPrompt: String` — 0 default values, 0 nullable fields, and 0 hardcoded language strings in `ChatUiMapper` or `ChatViewModel`.

## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Ensure the Tablet Landscape Chat screen (`ChatScreen`) permanently displays the real Phase 1 Improvement Areas (`InsightType.IMPROVEMENT`) generated by `GenerateInsightsUseCase` alongside the `CONSULTA LLIURE` ("Open Inquiry") card in the left pane, and maintain independent in-memory conversation threads per `topicId` in the right pane so Coach Jordi can conduct focused tactical dialogues for each improvement area.

### Non-Goals
* No persistent Room database storage for chat history (threads remain in-memory during the app session via `@Singleton ChatLocalDataSourceImpl`).
* No changes to `DashboardScreen` or `AnalysisScreen` UI layouts.
* No individual player statistics (Constraint #3).

### Job Story
When Coach Jordi opens the Chat screen directly or via "Explorar al Xat" from the Analysis screen,
I want the left panel to permanently list the real AI-detected Improvement Areas plus an Open Inquiry option and the right panel to show the conversation specific to the selected area,
so I can switch freely between tactical improvement threads without losing context or losing sight of the intervention areas list.

### Acceptance Scenarios

#### Scenario 1: Direct Navigation to Chat Loads Real Improvement Areas + Open Inquiry
* **Given** `GetPhase1GamesUseCase` returns the 14 Phase 1 games and `GenerateInsightsUseCase` returns AI insights (both `STRENGTH` and `IMPROVEMENT`)
* **When** Coach Jordi navigates to `ChatScreen` (`loadChat("")`)
* **Then** `ChatViewModel` loads both games and insights, `ChatUiMapper` filters only `InsightType.IMPROVEMENT` insights and maps them to `ChatTopicCardUiModel` items followed by the `CONSULTA LLIURE` (`id = "open_inquiry"`) card
* **And** the first Improvement Area is selected as `activeTopicId` (or `"open_inquiry"` if no improvement insights exist), and the left pane permanently displays `ChatTopicList`.

#### Scenario 2: Clicking an Improvement Area in Left Pane Switches Right Pane Thread
* **Given** `ChatViewModel` is in `ChatUiContent.Success` with multiple Improvement Area topics and `"open_inquiry"`
* **When** Coach Jordi sends a message in Topic 1, then clicks Topic 2 in the left pane (`onTopicSelected(topic2)`)
* **Then** the left pane remains `ChatTopicList` with `activeTopicId == topic2.id` highlighted
* **And** the right pane displays the empty conversation (or existing messages) for `topic2.id` without mixing messages from Topic 1
* **When** Coach Jordi clicks back on Topic 1 (`onTopicSelected(topic1)`)
* **Then** the right pane restores the messages previously sent in Topic 1.

#### Scenario 3: 'Explorar al Xat' Hand-off Selects Matching Improvement Area and Dispatches Prompt
* **Given** Coach Jordi taps "Explorar al Xat" on an Improvement Area card in `AnalysisScreen` passing `initialPrompt = insight.exploreChatPrompt`
* **When** `ChatScreen` executes `loadChat(initialPrompt)`
* **Then** `ChatViewModel` resolves `activeTopicId = insight.id` matching `initialPrompt`, keeps the left pane on `ChatTopicList` with that Improvement Area highlighted, and dispatches `sendMessage(initialPrompt)` into `insight.id`'s conversation thread once.

#### Scenario 4: Error Handling and Retry When Insights or Games Fail
* **Given** `GetPhase1GamesUseCase` or `GenerateInsightsUseCase` returns `Result.Error(DomainError.Network.NoInternet)`
* **When** `loadChat()` executes
* **Then** `ChatViewModel` transitions to `ChatUiContent.Error(DomainError.Network.NoInternet)`
* **When** Coach Jordi taps "Reintentar" (`onRetry()`) and the use cases succeed
* **Then** `ChatViewModel` transitions to `ChatUiContent.Success` with the mapped improvement topics.
