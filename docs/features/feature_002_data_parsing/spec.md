## 1. Source Feature & Idea Diagnosis
* **`id`:** `feature_002_data_parsing`
* **`area`:** `data`
* **`depends_on`:** `["feature_001_domain_models"]`
* **`status`:** `accepted`
* **`module_topology`:** `Layer-Based (:domain, :usecases, :data, :app)`
* **Objective:** Implement JSON deserialization and local repository data sourcing in `:data` to parse the 14-game Phase 1 dataset (`docs/general/dataset.json`) into the domain entities (`Game`, `Venue`, `Score`, `TeamStats`) and fulfill the `GameRepository` contract (`getPhase1Games()`, `getGameByRound(round)`).
* **Identified Ambiguities / Assumptions:**
  - *Dataset Asset Location*: The canonical dataset resides at `docs/general/dataset.json`. For runtime packaging and testability within `:data` (a pure Kotlin JVM library), the JSON is bundled into `data/src/main/resources/dataset.json` (or read via `InputStream` / `ClassLoader`), enabling unit tests to run fast without Android SDK/Context dependencies.
  - *Score and TeamStats Points Alignment*: In `dataset.json`, final scores are in `final_score.home_points` and `away_points`. In `TeamStats`, the `points` field defaults to `0`. The mapper populates `TeamStats.points` directly from the corresponding `home_points` and `away_points` to preserve complete statistical integrity.
  - *Serialization Framework*: In alignment with `dependency-manager`, either `kotlinx-serialization-json` or a lightweight zero-reflection JSON parser (e.g. `moshi` / `org.json`) is introduced cleanly in `libs.versions.toml`. DTOs in `:data` (`GameDto`, `ScoreDto`, `TeamStatsDto`) will map to pure domain models via extension functions (`toDomain()`), keeping `:domain` free of serialization annotations.
  - *In-Memory Caching*: Since the Phase 1 dataset is static (14 matches), `GameRepositoryImpl` can parse once and cache the resulting `List<Game>` in memory for fast synchronous subsequent lookups.
* **Necessary Questions:** None — all requirements clarified.

## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Provide a robust, type-safe data parsing pipeline and repository implementation in `:data` that loads the bundled 14-game Phase 1 dataset from JSON, transforms raw snake_case records into immutable domain models (`Game`, `Venue`, `Score`, `TeamStats`), and exposes them via `GameRepository` with typed `Result<T, DomainError>` error handling.

### Non-Goals
* No DevExpert API integration or AI prompt generation (owned by `feature_003_devexpert_client`).
* No use case interactors (owned by `feature_004_usecases`).
* No Room database persistence or SQLite migrations (static dataset; Room is reserved for dynamic offline caching if needed in future phases).
* No UI composables, ViewModels, or screen layouts (owned by `feature_005_dashboard_ui` in `:app`).
* No individual player statistics (strictly team-level box scores per `CONSTRAINTS.md`).

### Job Story
When the application initializes or queries historical basketball data,
I want the `:data` layer to parse the bundled Phase 1 dataset into structured domain models,
so that UseCases and ViewModels can reliably analyze all 14 matches, identify strengths and weaknesses, and calculate team performance trends.

### Acceptance Scenarios

#### Scenario 1: Parse Complete 14-Game Dataset
* **Given** the bundled Phase 1 dataset file (`dataset.json`)
* **When** `GameRepository.getPhase1Games()` is invoked
* **Then** it returns `Result.Success` containing a list of exactly 14 `Game` items in ascending chronological order from round 1 to round 14.

#### Scenario 2: Validate Home Match Parsing & Box Score Mapping (Round 1)
* **Given** the parsed dataset
* **When** inspecting Round 1 (`homeTeam = "BASQUETPIASABADELL BLAU"`, `awayTeam = "CB. CORNELLÀ"`, date = `"13/09/2026"`, time = `"16:15"`)
* **Then** `venue` contains `city = "Sabadell"`, `arena = "ESCOLA PIA SABADELL"`, `address = "GARCILASO, 99"`
* **And** `finalScore` is `homePoints = 62, awayPoints = 78`
* **And** `homeStats` has `ftPct = 52.4`, `fg2Pct = 42.1`, `fg3Pct = 21.4`, `efgPct = 38.6`, `offensiveRebounds = 5`, `defensiveRebounds = 16`, `totalRebounds = 21`, `turnovers = 19`, `assists = 8`, `astToRatio = 0.42`, `steals = 4`, `blocks = 1`, `secondChancePoints = 4`, `fastBreakPoints = 6`, `personalFouls = 22`, `points = 62`
* **And** `isHomeGame` is `true`, `isWin` is `false`, and `pointDifferential` is `-16`.

#### Scenario 3: Validate Away Match & Victory Outcome (Round 10)
* **Given** the parsed dataset
* **When** inspecting Round 10 (`homeTeam = "CEB SANT JORDI BLAU"`, `awayTeam = "BASQUETPIASABADELL BLAU"`, date = `"22/11/2026"`, time = `"19:30"`)
* **Then** `finalScore` is `homePoints = 65, awayPoints = 67`
* **And** `isHomeGame` is `false`, `isWin` is `true`, `opponentName` is `"CEB SANT JORDI BLAU"`, and `pointDifferential` is `+2`.

#### Scenario 4: Query Specific Match by Round via GameRepository
* **Given** an initialized `GameRepository`
* **When** `getGameByRound(3)` is invoked
* **Then** it returns `Result.Success` with the Round 3 match against `"CEB SANT JORDI BLAU"` (Score: 71 - 68, `isWin = true`).

#### Scenario 5: Handle Non-Existent Round Lookup
* **Given** an initialized `GameRepository`
* **When** `getGameByRound(99)` is invoked
* **Then** it returns `Result.Error(DomainError.Local.NotFound)`.

#### Scenario 6: Malformed JSON Resiliency
* **Given** corrupted or unparseable JSON content
* **When** `GameJsonParser` attempts to parse the payload
* **Then** it returns `Result.Error` with a `DomainError.Local.DatabaseError` or `DomainError.Generic` without crashing or throwing uncaught exceptions.
